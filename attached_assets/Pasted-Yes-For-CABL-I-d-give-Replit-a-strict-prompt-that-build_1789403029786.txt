Build a production-ready, database-driven Product Specifications System for the CABL e-commerce platform.

PRIMARY OBJECTIVE

Create a flexible specification architecture that allows CABL to store, manage, display, filter, and compare technical specifications for chargers and other electronics.

The system MUST support the 10 core comparison dimensions:

1. Maximum Power
2. Charging Protocols
3. Power Distribution
4. Ports
5. Charging Technology / GaN
6. Dimensions & Weight
7. Protection Systems
8. Efficiency & Thermal Features
9. Device Compatibility
10. Charging Capability

Do NOT solve this by adding dozens of hard-coded specification columns to "products".

Use a normalized relational design with dedicated tables for structured/complex specifications and a controlled attribute system for flexible specifications.

---

1. CORE PRODUCT

Do NOT duplicate existing product information.

Use the existing:

"products.id"

as the foreign-key reference.

Every specification must belong to a product through "product_id".

Use:

- UUID foreign keys where the existing schema uses UUID
- Proper foreign-key constraints
- Appropriate indexes
- "ON DELETE CASCADE" where appropriate
- Unique constraints to prevent duplicate specifications

Do not rename or modify existing product fields unless absolutely required.

Use human-readable labels in the frontend but stable slugs internally.

Maximum Power

---

17. DATA VALIDATION

Implement strict validation.

Examples:

power_w > 0
weight_g > 0
dimensions > 0
efficiency_percent BETWEEN 0 AND 100

Prevent:

65W
"65 watts"
"about 65"

from being stored in numeric fields.

Normalize manufacturer specifications before saving.

---

18. SOURCE / ACCURACY

Every technical specification must come from a reliable product source.

Never invent:

- charging protocols
- wattage
- PPS support
- GaN generation
- protection systems
- compatibility
- efficiency
- dimensions

If manufacturer data is unavailable, leave the value empty.

Optionally support:

"specification_source"

and:

"source_url"

for administrator reference.

Create indexes for:

product_id
attribute_id
attribute slug
numeric specification values
protocol relationships
compatibility relationships

Comparison queries must not require loading every product attribute into application memory.

Use SQL/database-level queries where practical.

- Do not duplicate product data.
- Do not create a giant "specifications" text column.
